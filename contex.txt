  2. Couche BFF — 21 modules KSM

  Le serveur BFF (src/server/) ne laisse aucun secret KSM transiter vers le
  navigateur :

  - ksm/client.ts : callKsm() injecte les headers (X-Client-Id, X-Api-Key,
  Bearer, X-Tenant-Id, X-Organization-Id)
  - session.ts : Hybrid cookie + Redis (SID dans cookie iron-session, session
  complète dans Redis, TTL configurable)
  - handlers.ts : authenticatedRoute() et requirePermissionRoute() — gardes pour
   les Route Handlers

  3. Gestion des rôles et permissions

  lib/roles.ts est la source de vérité côté frontend :

  - roleSlug(roles, permissions) — résout le rôle principal (par code, sinon par
   inférence des permissions)
  - entitledSlugs() — tous les espaces de travail accessibles (privilégié en
  premier)
  - isMigratedRole() — vérifie si un rôle a son arbre de routes dédié
  - Hiérarchie d'inférence : tenant:admin → hr-admin → payroll-manager → drh → 
  recruiter → doctor → accountant → controller → manager → employee

  hooks/use-can.ts :
  - useCan("hrm:expense:read") — vérifie si la session contient la permission
  - useCanAll([...]) — toutes les permissions requises
  - useHasRole("HR_DIRECTOR") — vérifie le code rôle

  Les permissions KSM arrivent avec suffixe #ORGANIZATION:<uuid> ; le frontend
  le strip systématiquement.
